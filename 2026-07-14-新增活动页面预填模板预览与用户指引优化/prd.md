# 业务需求文档: 新增活动页面预填模板预览与用户指引优化
> feature-id: 2026-07-14-新增活动页面预填模板预览与用户指引优化
> 状态: 草稿（暂存整合版）
> 日期: 2026-07-14
> 业务ID: 无

## 1. 背景与目标

当前系统在“新增活动”页面和“用户指引”功能上存在以下影响使用体验的问题：

1. 新增活动页面默认带有样例预填内容，用户虽然可以参考示例，但容易将示例内容误当成真实内容直接提交。
2. 模板预览体验偏弱，用户在上传或查看样例模板时，难以快速理解派单字段、回单字段及必填规则。
3. 页面缺少一键从“样例态”切换到“真实录入态”的操作，用户需要逐项手工清理预填信息。
4. 用户指引在跨页面使用时体验不连续，尤其是通过右下角“?”重新查看指引后，再进入“发起派单”“新增活动”等页面时，已配置的模块指引不能稳定保留。
5. 非首次登录用户从侧边菜单正常进入页面时，不应被反复自动打断，但又要保留手动查看指引的能力。

本次需求目标为：

- 保留样例内容的参考价值，同时避免样例内容被误提交。
- 优化新增活动页面的模板预览表达，让用户在提交前可以更直观地核对模板配置。
- 提供“重置”能力，让用户可以一键清空页面内预填写内容，快速进入真实录入状态。
- 明确并统一用户指引的触发规则，只在“首次登录”或“点击右下角 ?”时触发完整指引链路。
- 保证通过“?”进入的指引在跨模块、跨页面跳转时具备连续性，不仅限于新增活动页面，也覆盖其他已配置指引的模块。

## 2. 需求范围

### 2.1 本次包含

1. 新增活动页面基础信息区保留样例预填内容，但提交前必须替换成真实内容。
2. 新增活动页面提供“重置”按钮，一键清空页面内预填写和已填写的可编辑内容。
3. 新增活动页面优化模板预览展示效果，并在预览弹窗内补充用户可读的说明信息。
4. 样例模板允许预览参考，但不能直接作为正式提交模板使用。
5. 用户指引触发规则统一调整为：
   - 首次登录时自动触发全局与模块指引。
   - 点击右下角“?”时，不论第几次，都可以重新开启完整指引链路。
6. 通过“?”进入指引后，从全局指引进入“发起派单”、再进入“新增活动”等下级页面时，对应模块和页面的分步指引需要连续保留。
7. 同样的“?”重放机制适用于其他已配置分步指引的模块，不局限于新增活动页面。
8. 非首次登录用户从侧边菜单直接进入页面时，不自动触发模块分步指引，仅保留右下角“?”按钮供手动查看。

### 2.2 本次不包含

1. 不新增新的业务菜单、业务角色或权限体系。
2. 不调整活动提交流程本身的审批链路和流程引擎逻辑。
3. 不改变模板解析的业务口径，仅优化预览表现与提交限制。
4. 不扩展新的模板格式，仍按现有 xls/xlsx 范围处理。
5. 不在本次需求中重新设计全部模块指引内容，仅调整触发规则和保留机制。

## 3. 用户角色与使用场景

### 3.1 用户角色

1. 活动创建人员：需要进入“新增活动”页面创建派单活动。
2. 首次登录用户：首次进入系统时，需要通过全局和模块指引快速了解系统使用方式。
3. 非首次登录用户：日常使用系统的用户，需要尽量减少重复弹出的打扰，但在需要时可通过“?”重新查看指引。

### 3.2 使用场景

1. 用户进入新增活动页面，系统已带出样例信息，用户需要参考示例后改填真实信息。
2. 用户在查看模板样例或上传模板后，希望直接预览派单/回单字段效果，确认配置是否正确。
3. 用户不想逐项删除页面中的样例内容，希望点击一次按钮快速清空后开始真实填写。
4. 首次登录用户通过系统引导进入“发起派单”后，再进入“新增活动”，需要继续看到对应页面的分步指引。
5. 非首次登录用户从侧边菜单直接进入任意页面时，不希望系统自动打断；只有主动点击“?”时，才希望重新走一遍完整指引。

## 4. 业务流程

### 4.1 首次登录场景

1. 用户首次登录系统。
2. 系统自动弹出全局指引弹窗，展示主要业务模块。
3. 用户点击某个模块卡片进入对应页面。
4. 系统在进入该模块后自动展示对应分步指引。
5. 如果该模块还包含下级页面入口，例如从“发起派单”进入“新增活动”，则下级页面指引继续展示，不中断。
6. 当用户完成或跳过本轮指引后，系统保留右下角“?”按钮，供后续手动查看。

### 4.2 非首次登录直接进入页面场景

1. 非首次登录用户从侧边菜单进入某个业务页面。
2. 系统不自动弹出全局或模块分步指引。
3. 页面右下角保留“?”按钮。
4. 用户需要查看帮助时，手动点击“?”重新打开全局指引。

### 4.3 点击“?”重新查看指引场景

1. 用户点击右下角“?”按钮。
2. 系统重新打开全局指引弹窗。
3. 用户点击任意模块卡片进入对应模块。
4. 系统开启一次完整的“指引重放链路”，保证该模块及其后续相关页面的分步指引重新展示。
5. 同一轮重放中，用户进入的相关页面都应按照已配置规则展示对应指引。

### 4.4 新增活动页面使用场景

1. 用户进入新增活动页面。
2. 系统展示样例活动名称、活动内容、活动要求，并展示样例模板文件供预览参考。
3. 用户可以先查看样例模板预览，了解派单字段和回单字段结构。
4. 用户有两种处理方式：
   - 直接逐项替换样例内容并上传正式模板。
   - 点击“重置”按钮，清空页面内预填写内容后再录入真实信息。
5. 用户完成真实信息填写、上传正式模板、完成流程模型配置后，才可提交。

## 5. 功能需求

### 5.1 新增活动页面样例预填展示

1. 新增活动页面在首次进入时，保留活动名称、活动内容、活动要求的样例值展示。
2. 样例值仅作为填写参考，不代表可以直接提交。
3. 页面应明确提示用户：样例内容必须替换成真实活动信息后，才能提交。

### 5.2 新增活动页面“重置”按钮

1. 页面底部在“确定”“取消”之外新增“重置”按钮。
2. 用户点击“重置”后，系统弹出确认提示，防止误清空。
3. 用户确认后，页面内预填写和已填写的可编辑内容被清空，进入真实录入状态。
4. 清空后，页面应能够继续正常录入、上传模板和提交流程配置。
5. 清空后需给用户明确提示，例如“预填写信息已清空，请填写真实活动信息”。

### 5.3 模板预览优化

1. 模板预览弹窗需要以更直观、结构化的方式展示派单对象信息和回单信息。
2. 预览弹窗中需要增加“预览说明”，让用户明确当前看到的是样例模板还是上传模板。
3. 派单信息区域应能清晰展示字段名称和字段规则（例如是否必填）。
4. 回单信息区域应能展示回单字段的控件形态和配置效果，帮助用户核对单选、多选、数字、日期等内容。
5. 当用户查看的是样例模板时，应明确说明样例仅供参考，不能直接作为正式提交依据。
6. 当用户查看的是上传模板时，应明确说明这是系统解析后的结果，用户应重点核对字段名称、必填项和回单配置。

### 5.4 样例模板与正式模板区分

1. 页面可回显样例模板文件，方便用户点击预览参考。
2. 样例模板只用于参考预览，不能作为正式提交模板。
3. 用户要发起活动时，必须上传自己的正式模板文件。
4. 若用户仍保留样例模板或未上传正式模板，系统应阻止提交并明确提示原因。

### 5.5 提交前校验与提示

1. 提交前，系统应校验以下内容是否满足：
   - 活动名称已替换为真实值。
   - 活动内容已替换为真实值。
   - 活动要求已替换为真实值。
   - 已选择客户类型。
   - 在 Excel 上传场景下，已上传正式模板。
   - 已完成流程模型及任务类型配置。
2. 当校验不通过时，页面应以清单形式提示用户还缺什么。
3. “确定”按钮在不满足提交条件时应不可提交或不可生效。

### 5.6 用户指引触发规则统一

1. 首次登录：自动展示全局指引，并在进入模块后自动展示模块分步指引。
2. 非首次登录：从侧边菜单直接进入页面时，不自动展示模块分步指引。
3. 右下角“?”：无论用户已经使用过多少次，只要点击“?”，都应允许重新开启完整指引链路。
4. 点击“?”后再进入模块时，应按该轮指引重放逻辑重新展示对应模块分步指引。

### 5.7 指引跨页面保留

1. 从“?”打开的全局指引进入“发起派单”后，再进入“新增活动”，新增活动页面指引应继续保留。
2. 该规则不仅适用于新增活动页面，也适用于其他已配置分步指引的模块。
3. 指引的连续性应基于一次完整的“手动重放会话”来理解，而不是只在单个页面内生效。

## 6. 业务规则

1. 样例信息可展示，但样例信息不可直接提交。
2. 样例模板可预览，但样例模板不可直接作为正式模板提交。
3. 点击“重置”后，用户需要自行重新填写真实活动信息，不能自动恢复样例值。
4. 只有首次登录用户，才会在正常进入系统后自动看到全局/模块指引。
5. 非首次登录用户通过侧边菜单直接进入业务页面时，不自动弹模块指引。
6. 右下角“?”始终作为手动查看帮助的统一入口存在。
7. 每次通过“?”开启指引时，都视为一次新的手动重放会话，本轮进入的已配置模块应按重放规则展示指引。
8. 模板预览需要区分“样例模板预览”和“上传模板预览”两种状态，并给出对应说明。

## 7. 数据口径与状态说明

1. “样例内容”指系统默认展示给用户参考的活动名称、活动内容、活动要求以及样例模板文件。
2. “真实内容”指用户实际要提交的活动名称、活动内容、活动要求和正式模板文件。
3. “首次登录”以系统登录接口返回结果为准，当接口明确判断为首次登录时，触发首次登录引导。
4. “手动重放会话”指用户点击右下角“?”后开始的一轮完整指引流程，用于保证跨页面指引连续性。
5. “模块分步指引”指已为某个页面或模块配置的逐步操作说明，例如活动管理、新增活动、待办任务、进度查询、下载中心等页面的分步说明。

## 8. 需拍板的业务决策

### 8.1 已确认

1. 非首次登录用户，从侧边菜单直接进入页面时，不需要自动弹出模块指引。
2. 首次登录时，需要自动展示全局和模块指引。
3. 点击右下角“?”时，不论第几次，都应重新触发完整指引链路。
4. 新增活动页面需要新增“重置”按钮，用于清空预填写信息后录入真实信息。
5. 样例模板不能直接用于正式提交。

### 8.2 【待确认】

1. “重置”按钮清空范围是否仅限用户可编辑的页面内容，系统自动带出的基础标识信息是否保留。
2. 右下角“?”触发的指引重放会话，在用户跨多个模块连续浏览时，是否需要整轮持续生效，还是进入首个目标模块后即可结束。
3. 模板预览中的说明文案是否需要进一步统一成业务侧标准话术。

## 9. 权限与可见性

1. 本次需求不新增权限角色，仍沿用现有页面访问权限。
2. 只有已有对应页面访问权限的用户，才能进入相应模块并看到对应页面指引。
3. 如某个按钮、页面入口或操作由于权限原因不显示，用户指引可保留说明“如未显示请联系管理员”。
4. 右下角“?”按钮作为全局帮助入口，对已进入系统的用户可见。

## 10. 异常与边界场景

1. 用户未替换样例内容就尝试提交时，系统应明确提示需要先填写真实活动信息。
2. 用户未上传正式模板就尝试提交时，系统应明确提示样例模板不能直接提交。
3. 用户点击“重置”后，如已填写部分真实内容，也一并清空，应在确认提示中提前告知。
4. 用户在重置后直接上传模板，但未选择客户类型时，系统应先提示选择客户类型。
5. 用户通过“?”进入全局指引后，如果跳转到已配置指引的页面，应继续展示对应指引；如果跳转到未配置指引的页面，则仅保留“?”按钮，不强制展示分步内容。
6. 首次登录接口异常时，系统不应阻塞用户使用页面，但应至少保留“?”按钮，供用户手动查看帮助。

## 11. 验收标准

1. 首次登录用户进入系统后，自动看到全局指引弹窗。
2. 首次登录用户从全局指引进入“发起派单”，再进入“新增活动”时，对应分步指引可以连续展示。
3. 非首次登录用户通过侧边菜单直接进入任意已配置指引页面时，不自动弹分步指引。
4. 任意用户点击右下角“?”后，都可以重新打开全局指引，并在进入对应模块后看到该轮重放的分步指引。
5. 新增活动页面进入时，仍能看到样例活动信息和样例模板作为参考。
6. 新增活动页面点击“重置”后，页面内预填写和已填写的可编辑内容被清空，用户可立即填写真实信息。
7. 样例模板可以预览，但不能直接用于正式提交。
8. 用户上传正式模板后，可以在优化后的预览弹窗中核对派单字段和回单字段效果。
9. 当活动名称、活动内容、活动要求仍为样例内容，或未上传正式模板、未完成流程配置时，系统不能让活动成功提交。

## 12. 待确认项

1. “重置”按钮清空后，是否需要保留系统自动生成的活动编码、发起人、发布部门等非用户手工输入信息。
2. 手动点击“?”后开启的指引重放链路，是否需要在整轮会话内覆盖所有后续进入的已配置模块。
3. 模板预览说明文案是否需要统一为业务部门标准表达。
4. 对于其他已配置指引模块，是否需要同步补充类似“重放中”或“重新查看”之类的视觉标识，帮助用户理解当前处于手动指引状态。
