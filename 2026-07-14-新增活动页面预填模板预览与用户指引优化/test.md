# 测试文档：新增活动页面预填模板预览与用户指引优化

> feature-id: 2026-07-14-新增活动页面预填模板预览与用户指引优化
> 测试日期：2026-07-15
> 关联文档：[prd.md](./prd.md) | [plan/index.md](./plan/index.md) | [retrospective.md](./retrospective.md)
> 测试范围：新增活动页样例态/真实态切换、提交控制、重置回收，以及全局用户指引的首次登录触发、侧边菜单进入、右下角 ? 重放链路

## 1. 测试环境与前置准备

### 1.1 环境

- 前端：本地 dev server，账号需具备“新增活动”“发起派单”“待办任务”等菜单访问权限。
- 后端：`/isFirstLogin` 接口需可按用例返回 `true` / `false`（或前端临时 mock）。

### 1.2 测试账号准备

| 账号类型 | 说明 | 准备方式 |
|---|---|---|
| 首次登录账号 | `/isFirstLogin` 返回 `data: true` | 后端重置该账号首次登录标记，或前端临时强制 `isFirst = true` |
| 已登录过账号 | `/isFirstLogin` 返回 `data: false` | 正常使用过一次的账号 |

### 1.3 测试前必做清理

每个用例开始前，清理浏览器存储，避免历史残留干扰（尤其是重放 session 残留，曾导致“todo 有指引、activity 没有”的假象）：

- **localStorage**：删除 `user_guide_global_done`、所有 `user_guide_module_v2_*`。
- **sessionStorage**：删除 `user_guide_first_login`、`user_guide_replay_active`、`user_guide_replay_shown_v1`。
- 最简方式：DevTools → Application → Clear site data，或关闭浏览器标签后重开。

> ⚠️ 重点：`user_guide_replay_active` 与 `user_guide_replay_shown_v1` 若不清理，会跨登录泄漏，制造不可复现的指引假象。

## 2. 核心规则与用例总览

本 feature 验收收敛为四条核心规则，所有用例围绕它们展开：

| 规则 | 描述 | 对应用例章节 |
|---|---|---|
| R1 | 首次登录：有指引弹窗，新增活动页有示例假数据，点击重置清空全部假数据并隐藏重置按钮 | §3.1、§3.2 |
| R2 | 已登录过（接口返回 false）：无指引弹窗，新增活动页示例数据全部清空 | §3.3 |
| R3 | 点击右下角 ?：弹出指引，进入对应模块及二级页面（尤其新增活动页）都保留指引 | §3.4 |
| R4 | 已登录过、侧边菜单进入有指引的页面：不自动展示页面指引 | §3.5 |

## 3. 功能用例

| T3.1.1 | 首次登录账号登录系统 | 自动弹出全局指引弹窗（模块卡片总览），无 `?` 按钮遮挡弹窗 | ☐ |
| T3.1.2 | 在全局弹窗点击“发起派单”卡片 | 跳转活动管理列表页，自动展示活动管理分步指引气泡 | ☐ |

## 4. 边界与异常用例

### 4.1 keep-alive 缓存复用

**背景**：新增活动页受 keep-alive 缓存，离开再返回时是 `activated` 复用而非重新 `created`，需验证态切换策略在缓存复用下仍生效。

| 用例 ID | 步骤 | 预期结果 | 结果 |
|---|---|---|---|
| T4.1.1 | 首次登录进入新增活动页（示例态）→ 离开 → 再次进入 | 仍为示例态（示例数据恢复展示），不重复追加样例模板文件 | ☐ |
| T4.1.2 | 首次登录进入新增活动页 → 点重置清空 → 离开 → 再次进入 | 仍为干净表单（示例数据清空），无样例残留 | ☐ |
| T4.1.3 | 已登录过进入新增活动页（干净态）→ 离开 → 再次进入 | 仍为干净表单，无示例残留、无自动选中模型 | ☐ |
| T4.1.4 | 首次登录示例态 → 切到已登录账号（登出再登录）→ 进入新增活动页 | 干净表单（示例数据清空，无流程模型/样例接单人/双线残留） | ☐ |

> 📌 T4.1.4 对应复盘中的“中间态残留”问题（基本信息已清但流程模型残留），需重点回归。

### 4.2 用户已填真实数据保留

| 用例 ID | 步骤 | 预期结果 | 结果 |
|---|---|---|---|
| T4.2.1 | 已登录过进入新增活动页 → 填写真实活动名称（非【示例】）→ 离开 → 再次进入 | **保留**用户填写的真实数据，不被清空 | ☐ |
| T4.2.2 | 已登录过进入新增活动页 → 上传正式模板（非样例）→ 离开 → 再次进入 | **保留**正式模板，不被清空 | ☐ |

> 📌 `hasRealUserData` 判据需确保不误清用户真实数据。`customerType` 示例值“2”与合法值无法区分，刻意不纳入判断——若用户只选了客户类型未填其他，再次进入时客户类型可能被清，属已知取舍，需业务确认是否接受。

## 5. 自动化与回归建议

### 5.1 回归重点

每次相关代码变更后，至少回归以下高风险用例（均来自本轮返工）：

1. **T3.2.5 / T3.2.6**——重置后示例数据彻底清空、双线不残留、重置/提交卡片隐藏。
2. **T3.3.3 / T3.3.4**——已登录过进入新增活动页，示例数据全部清空（含流程模型/样例接单人/双线）。
3. **T4.1.4**——keep-alive 缓存 + 账号切换的中间态清理。
4. **T4.5.3 / T4.5.4**——流程模型接口空时，示例态与非示例态的“双线”兜底差异。
5. **T3.4.3 / T3.4.4**——? 重放链路进入新增活动页的示例数据恢复与指引连续。

### 5.2 自动化测试缺口

当前仓库对本 feature 无前端单元/端到端测试覆盖（ESLint 对 Vue 文件存在历史噪音，不能作为质量门槛）。建议后续补：

- `applySampleDataPolicy` 的纯逻辑测试（输入 sessionStorage/localStorage 状态 → 期望 isSampleMode/ formData 状态），覆盖示例态、干净态、中间态、真实数据保留四类。
- `hasRealUserData` 计算属性的边界用例（仅 customerType、仅正式模板、混合示例与真实）。
- `ProcessModelConfig` 的 `initial` 开关对 `loadTaskTypes` / `loadProcessModels` 兜底分支的影响。
- 重放 session 的写入/去重/清理生命周期。
