# LOCAL-20260727-180034 需求文档目录增加版本日期前缀 需求文档

## 文档信息

- 需求号：`LOCAL-20260727-180034`
- 需求名称：需求文档目录增加版本日期前缀
- 单据类型：Requirement

## 背景与现状

当前新需求目录使用 `<需求号>-<标题>`，目录内 Markdown 文件使用 `<需求号>-<标题>-<文档类型>.md`。目录无法直接体现需求版本日期，按日期浏览或归档时不够直观。

## 目标

新建需求或 Bug 档案时，由用户提供版本日期，目录统一使用 `<YYYY-MM-DD>-<需求号或Bug号>-<标题>`；目录内 Markdown 文件名继续保持 `<需求号或Bug号>-<标题>-<文档类型>.md`，不增加日期前缀。

## 业务场景

项目成员通过 `project-intel intake` 新建需求或 Bug，并明确提供版本日期。日期可使用 `2026-07-23`、`7.23`、`7月23日` 等形式；未写年份时按当前年份补全。用户提供本地需求文档并告知需求号、标题和版本时，Agent 同样把版本日期传入 intake。系统将输入规范化为 `YYYY-MM-DD`，并在后续 spec、design、test、finish、maintain 阶段持续解析同一目录。

## 范围

- 新档案目录增加 `YYYY-MM-DD-` 前缀。
- Intake 增加并持久化用户输入的版本日期。
- Project Intelligence 接入说明要求在实施型需求中收集需求号、标题和版本日期。
- 目录长度限制包含日期前缀，仍不超过 240 UTF-8 字节。
- 需求号解析、重复档案检测和证据作用域识别支持新目录。
- 兼容已有 `<需求号>-<标题>`、纯 `<需求号>` 和 `by-id` 目录。
- 目录内需求、设计、实施计划、测试、收口文档文件名保持现有规则。

## 非目标

- 不批量重命名已有需求档案。
- 不改变外部接口、命令参数或文档正文模板。
- 不修改包版本和发布元数据。

## 业务规则与异常边界

- 版本日期格式固定为 `YYYY-MM-DD`。
- 版本日期必须由用户输入，不允许静默使用档案创建当天。
- 完整日期接受 `YYYY-MM-DD`、`YYYY.MM.DD`、`YYYY/MM/DD`；省略年份时接受 `M.D`、`M月D日`，并使用当前年份补全。
- 输入必须是真实日历日期，非法日期应在创建档案前报错。
- 规范化后的版本日期写入 manifest 并随目录持久化；后续操作不得因跨日而切换目录。
- 标题继续执行跨平台非法字符清理和 UTF-8 字节截断。
- 新旧目录同时存在且 manifest 指向同一需求号时，按重复档案拒绝处理，避免误写。
- 旧档案没有版本日期字段时仍按原目录正常读取。

## 验收标准

- AC-01：新建 Requirement 和 Bug 的目录均为 YYYY-MM-DD-编号-标题
- AC-02：目录内各类 Markdown 文件名不包含版本日期
- AC-03：旧编号标题、纯编号和 by-id 档案仍可读取和流转
- AC-04：新目录参与重复档案检测与证据作用域过滤且不超过 240 UTF-8 字节
- AC-05：Intake 规范化并持久化用户版本日期且拒绝缺失或非法日期
- AC-06：Project Intelligence 接入说明要求收集版本日期并传给 intake

## 外部接口影响

不影响外部接口。改动仅涉及仓库内 `.project-intel/requirements/` 的目录生成与解析规则和本地 CLI intake 参数，不改变网络接口。

## 待确认事项

无。版本日期由用户明确提供；省略年份时使用当前年份。
