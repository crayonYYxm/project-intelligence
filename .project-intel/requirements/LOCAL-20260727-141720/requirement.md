# LOCAL-20260727-141720 需求与 Bug 目录使用编号加标题 需求文档

## 文档信息

- 需求号：LOCAL-20260727-141720
- 需求名称：需求与 Bug 目录使用编号加标题
- 单据类型：Requirement

## 背景与现状

当前需求与 Bug 的生命周期文件统一存放在 `.project-intel/requirements/<id>/`。目录只显示编号，浏览文件树时无法直接判断单据内容，需要逐个打开 `requirement.md` 或 `manifest.json`。

## 目标

新建需求与 Bug 时，使用“编号-标题”作为生命周期目录名，在不打开文档的情况下即可识别单据主题；同时保持按需求编号执行所有 CLI 命令，并兼容既有目录。

## 业务场景

1. 用户登记 Requirement 后，生成 `.project-intel/requirements/<id>-<标题>/`。
2. 用户登记 Bug 后，生成 `.project-intel/requirements/<bug-id>-<标题>/`。
3. 用户继续操作历史需求时，CLI 仍可通过 `--requirement-id <id>` 读取仅编号目录和旧版 `by-id/<id>` 目录。
4. 标题包含 Windows/macOS/Linux 不允许或容易造成歧义的路径字符时，CLI 生成跨平台安全且稳定的目录名。

## 范围

- 需求目录名生成与解析。
- 生命周期 manifest、需求/设计/计划/测试/收口文档路径。
- 需求查询、历史布局迁移和范围证据识别。
- 对应单元测试及用户可见文档说明。

## 非目标

- 不自动批量重命名现有 `.project-intel/requirements/<id>/` 目录。
- 不修改需求编号格式、生命周期状态机或文档正文文件名。
- 不改变外部服务 API。

## 业务规则与异常边界

1. 新目录格式固定为 `<规范化编号>-<安全标题>`。
2. 标题保留中文、字母、数字和常见安全字符；路径分隔符、控制字符及 Windows 禁止字符统一替换为 `-`，连续分隔符折叠。
3. 标题清洗后为空时使用稳定兜底词，目录名不得以空格或句点结尾，并限制单个目录段长度。
4. 通过编号加载时优先匹配 manifest 内 `requirementId`，兼容历史 `<id>` 与 `by-id/<id>`；若出现多个同编号档案，必须报明确歧义错误，不得静默选错。
5. manifest 内记录的 artifact 路径必须使用实际目录名，范围证据判断不得继续硬编码 `<id>/`。

## 验收标准

- AC-01：新建 Requirement 或 Bug 后，实际目录名为规范化编号-安全标题，且所有生成文档与 manifest artifact 路径均指向该目录。
- AC-02：标题含空格、中文、斜杠、反斜杠、Windows 禁止字符、控制字符或尾随句点/空格时，生成结果跨平台安全、非空且稳定。
- AC-03：仅提供需求编号时，可继续读取和更新新的编号-标题目录、历史仅编号目录及旧版 by-id/<id> 目录。
- AC-04：需求查询、旧布局迁移、测试证据与收口路径不因目录名变化而失效；同编号存在多个档案时返回明确错误。

## 外部接口影响

不影响外部接口。CLI 参数保持 `--requirement-id` 不变，但新建生命周期档案的本地目录路径会变化；通过兼容解析保障既有目录可继续使用。

## 待确认事项

无。默认以连字符连接编号与标题，不自动重命名历史档案。
