# 场景分析

## 场景分析

### 场景一：新建可读的需求目录

- 场景名称：新建 Requirement 或 Bug 生命周期档案
- 参与对象：CLI 使用者、需求生命周期状态机、本地文件系统
- 前置条件：用户提供需求编号和标题，项目已初始化 `.project-intel`
- 处理过程：CLI 规范化编号并清洗标题，将两者以连字符组合为目录名，再在该目录写入 manifest 和各阶段文档
- 目标结果：文件树直接显示编号和标题，后续命令仍只需传入需求编号
- 异常边界：标题含跨平台禁止字符、控制字符、尾随句点或空格时统一生成安全名称；清洗后为空时使用稳定兜底名称

### 场景二：继续处理历史需求

- 场景名称：按编号读取历史档案
- 参与对象：CLI 使用者、需求目录解析器、历史 manifest
- 前置条件：项目中存在新“编号-标题”、旧“仅编号”或旧版 `by-id/编号` 目录
- 处理过程：解析器先读取候选目录中的 manifest 并核对 `requirementId`，唯一匹配后返回真实目录；后续生成、测试和收口均复用该目录
- 目标结果：升级后历史需求无需重命名即可继续执行全部生命周期命令
- 异常边界：同一编号存在多个匹配档案时返回明确歧义错误，不按目录遍历顺序静默选取

### 场景三：查询与迁移生命周期档案

- 场景名称：列出需求和迁移旧版 `by-id` 布局
- 参与对象：需求查询命令、布局迁移命令、manifest artifact 路径
- 前置条件：项目包含一种或多种历史布局
- 处理过程：查询从 manifest 获取真实需求编号；迁移目标目录使用 manifest 标题生成“编号-标题”，并把 artifact 中的旧路径改写为实际新路径
- 目标结果：查询结果不暴露目录名作为需求编号，迁移后文档路径全部有效
- 异常边界：缺少可用标题时迁移使用稳定兜底词；目标目录已存在时保持幂等，不覆盖既有档案

## 风险考虑

路径解析属于生命周期公共能力，错误会同时影响需求生成、测试证据、review、finish 和 maintain。通过集中解析、旧布局回退、歧义阻断和全量回归降低风险。

紧急方案：

若新版解析出现回归，回退相关提交即可；历史目录不自动重命名，因此不会产生不可逆数据迁移。

# 实现方案

### 需求目录解析与命名

- 改造目的：为新档案生成可读目录，并以编号稳定解析新旧目录
- 当前与目标：当前固定拼接 `<id>`；目标是创建时拼接 `<id>-<安全标题>`，读取时解析实际目录
- 处理规则：编号沿用 `normalizeId`；标题单独清洗 Windows 禁止字符、路径分隔符和控制字符，折叠连续分隔符并限制长度；候选目录必须通过 manifest 的 `requirementId` 校验
- 字段流转：需求编号与需求名称 → 编号规范化与标题清洗 → 目录段 → manifest 实际路径
- 调用顺序：intake 创建档案时确定新目录；后续状态机通过编号解析同一目录；找不到时回退旧版 `by-id`
- 异常与兼容：优先使用唯一的 manifest 身份匹配；兼容仅编号目录；重复匹配时报错
- 源码依据：`src/requirements/state-machine.ts#requirementDir`
- 源码依据：`src/requirements/state-machine.ts#activeManifestPath`
- 源码依据：`src/requirements/state-machine.ts#createRequirement`

### 查询与布局迁移

- 改造目的：避免把“编号-标题”目录段误当成需求编号，并确保迁移结果采用新格式
- 当前与目标：当前查询直接收集目录名，迁移目标固定为 `<id>`；目标是从 manifest 读取编号，迁移时按编号和标题生成目标目录
- 处理规则：查询只返回有效 manifest 的身份；迁移读取旧 manifest 的 `requirementName` 生成目标目录，并按实际目录前缀改写 artifact 路径
- 字段流转：目录候选 → manifest → 需求编号/标题 → 查询结果或迁移目标路径
- 调用顺序：查询扫描 v2 与 legacy 候选后加载 manifest；迁移先读取 legacy manifest，再复制并改写路径
- 异常与兼容：不删除 legacy 源目录；已有目标不覆盖；缺标题使用兜底词
- 源码依据：`src/commands/requirement.ts#runRequirement`
- 源码依据：`src/requirements/layout.ts#migrateLayout`
- 源码依据：`src/requirements/layout.ts#rewriteManifestPaths`

### 证据范围与用户文档

- 改造目的：让测试证据识别和使用说明跟随实际目录，不再硬编码 `<id>/`
- 当前与目标：当前范围判断拼接需求编号；目标是依据解析后的真实目录相对路径判断
- 处理规则：比较规范化后的实际需求目录前缀；文档统一展示 `<id>-<title>`，并声明旧目录兼容
- 字段流转：需求编号 → 实际需求目录 → 仓库相对路径 → 证据文件分类
- 调用顺序：捕获 Git 变更时解析实际目录，再将生命周期文档排除出业务变更范围
- 异常与兼容：历史目录仍可被正确识别，仓库外路径继续拒绝
- 源码依据：`src/requirements/scope.ts#isUnderRequirementDir`
- 源码依据：`src/commands/init.ts#runInit`
