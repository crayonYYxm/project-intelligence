# LOCAL-20260728-114105 强制生成四类生命周期文档 实施计划

## 实施范围

在现有 schemaVersion 2 和命令表面内收紧文档动作：新需求默认生成 spec 与设计文档，禁止四类必选文档延期；仅提供设计文档时由 Project Spec 先提炼 spec；测试与 finish 分别保证测试文档和收口文档落盘。同步插件 Skills、Codex/Claude/ZCode managed rules、README、指南和契约测试。改动采用 inline 模式，因为状态机、命令和 Skill 文案共享同一动作约束，拆分并行编辑容易产生规则漂移。

Global Constraints：

- 保持用户输入版本日期，不回退为系统自动日期。
- 不改动外部路径安全逻辑、npm 发布流程、插件清单和历史目录解析。
- `register` 继续支持已有文档；canonical 标题化文件仍写入当前需求目录。
- 实施计划保持可选，四类必选文档不可 defer。
- 行为验证必须包含真实测试计数，并记录 RED、GREEN、回归和 AC 映射。

## 风险与回滚

- 风险：动作枚举收紧会使仍传 `later` 的旧自动化失败；Skill/CLI 同步错误可能造成宿主行为不一致；共享 `generateArtifact` 与 finish 路径为高影响区域。
- 回滚：回退本需求提交即可恢复旧动作行为。没有 schema 迁移、历史文件删除或外部状态变更；已存在的四类文档和历史 manifest 可继续读取。
